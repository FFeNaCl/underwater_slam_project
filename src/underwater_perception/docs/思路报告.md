## 1. 项目目标与系统边界

### 1.1 目标

用**单个单目相机**在水下完成三件事：

1. **定位与建图**：估计相机轨迹，构建稀疏三维点云；
2. **目标识别**：识别水下真实环境中的静态目标（标定立方体、标记板、管道等）；
3. **语义地图**：把识别到的目标放到 SLAM 地图里，形成“带语义的三维地图”。

### 1.2 系统不是什么

必须提前讲清楚，否则答辩容易被问穿：

* **不是稠密重建**：ORB-SLAM3 输出的是稀疏特征点云，不是 Mesh/TSDF/NeRF；
* **不是绝对尺度**：单目 SLAM 地图单位由初始化基线决定，**不是米**；
* **不是多传感器融合**：没有 IMU、深度相机、DVL、压力计；
* **不是端到端学习**：检测可以用 YOLO，但几何、标定、三角化、SLAM 都是传统几何方法。

### 1.3 当前数据流

```text
真实单目相机 / USB 相机
        │ /image_raw
        ▼
image_enhancer_cpp（红通道补偿 + 灰世界 + CLAHE + 可选去畸变）
        │ /image_enhanced
        ├──────────────────────────────┐
        ▼                              ▼
yolo_detector（真实环境，best.pt）   cube_detector（几何旁路，红色立方体）
        │ /yolo/detections              │ /detections
        └──────────────┬────────────────┘
                       ▼
              semantic_landmark（检测 + SLAM 位姿 -> 多视图三角化）
                       │ /semantic/landmarks + /semantic/markers
                       ▼
                    RViz2

并行的 SLAM 链路：
/image_enhanced -> slam_input_bridge -> ORB-SLAM3 mono_node_cpp
                                          │ /slam/pose /slam/path /slam/map_points /slam/status
                                          ▼
                                       RViz2
```

**设计要点**：检测器与 SLAM 解耦。几何旁路和 YOLO 输出同一条消息契约
（`/detections` 的超集），下游地标节点不需要知道检测器换了。

## 3. 算法逐项审查

### 3.1 相机标定

#### 3.1.1 现有流程

`core/calibration.py`：

1. `detect_pattern()`（约 L200）：优先 `findChessboardCornersSB`，失败回退经典算法；
2. `validate_corners()`（L153）：用单应矩阵检查“检出的点是否构成规整点阵”，
   防止检测器锁到偏移/外扩的网格；
3. `cornerSubPix` 亚像素优化；
4. `calibrate()`（L340）：`cv2.calibrateCamera` + 逐视图重投影误差 + 警告；
5. `write_all_outputs()`（L690）：一次写 `ost.yaml` / ORB-SLAM3 yaml / 增强参数 / JSON 报告。

#### 3.1.2 做得对的地方

* **角点几何校验**：这是很多标定脚本没有的。实测踩过“48 个角点全检出但整体偏一格”的坑，
  单应残差能拦住。
* **输出四件套**：标定结果直接进入 SLAM、增强、报告，避免手工抄数字。
* **逐视图误差与覆盖度警告**：不是只看 RMS，能指出最差视图。
* **单位约定明确**：`square_size` 用米，`cols/rows` 是**内角点**。
* **合成数据可回归**：`calibration_math` 自测 fx 误差 0.80%、fy 0.81%、主点 2.37 px、RMS 0.408 px（18 视图）。

#### 3.1.3 已知问题

| # | 问题 | 证据 | 影响 | 建议 |
|---|---|---|---|---|
| C1 | **只支持针孔 + 径向/切向畸变** | `calibrate()` 固定 `cv2.calibrateCamera` | 平面防水壳的“空气-玻璃-水”折射不是针孔模型，画面边缘误差大 | 报告中明确限制；高精度场景换球面端口或折射模型 |
| C2 | **ChArUco 路径不可靠** | `detect_pattern()` L240-261：`detectMarkers` 被调用两次，且 `view_from_array` 仍用 `chessboard_object_points`，ChArUco 角点 ID 与物体点不对应 | 用 ChArUco 会“检出但标定错误” | 当前版本**只用棋盘格**；ChArUco 标为实验性，或按 `charuco_ids` 生成物体点 |
| C3 | **圆点阵列没有几何校验** | 只有棋盘格调用 `validate_corners` | 圆点板可能锁到错网格 | 给 `findCirclesGrid` 也加单应校验 |
| C4 | **`fix_aspect_ratio` 风险** | `calibrate()` 的 flags | 若传感器像素不是正方形，强行固定会引入系统误差 | 默认关闭；只有确认 sensor 规格时再开 |
| C5 | **自动采集缺少模糊/重复帧过滤** | `calibration_node.py` 只按时间间隔采集 | 同一姿势重复多张，覆盖度虚高 | GUI 已加 `is_novel_view`；ROS 节点后续也加 |
| C6 | **没有留出验证集** | 所有视图同时参与求解与 RMS 统计 | RMS 偏乐观 | 留 20% 视图做 hold-out，报“训练 RMS / 验证 RMS” |
| C7 | **未比较畸变模型** | 只用 5 参数 plumb_bob | 水下广角可能更适合 fisheye/rational | 增加模型选择实验（OpenCV fisheye / rational） |
| C8 | **真实水下未验证** | 合成数据 | 不能声称“水下标定精度已达标” | 按 `docs/CALIBRATION.md` 实测，记录 RMS/去畸变图 |

#### 3.1.4 本次新增：可改标定板参数的 GUI

`tools/calibrate_gui.py` 已实现并用本机 Tk 冒烟测试通过：

* 图案：棋盘格 / 圆点阵列；
* 内角点 `cols/rows`、方格边长（毫米）可改；
* 实时显示“内角点 8x6；方格 9x7；物理尺寸 225×175 mm”，防止“9x7 格误填成 9x7 内角点”；
* USB 相机 / 视频 / 图片文件夹三种来源；
* 自动采集带**相似视图抑制**；
* 标定后自动写四件套 + 去畸变示例。

> 现场建议：先在空气中标一次做基线，再在**实际水深/防水壳/镜头-玻璃距离**下标一次；
> 两次结果对比，能直观看到折射影响。

### 3.2 水下图像增强

#### 3.2.1 现有流程

`image_enhancer_cpp/src/enhancer.cpp`：

1. 红通道补偿：按 B/G 均值提升 R，增益上限 `red_gain_limit=2.5`；
2. 灰世界白平衡：三通道均值拉到同一灰度；
3. CLAHE：在 LAB 的 L 通道做局部对比度；
4. 可选 unsharp mask；
5. 可选去畸变（标定后填内参）。

#### 3.2.2 问题

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| E1 | **灰世界假设在水下不成立** | 水下背景偏蓝绿，不是灰色；白平衡会把整体色调拉偏 | 只在非水体区域估计白平衡，或改用水下专用先验 |
| E2 | **红补偿与灰世界互相抵消** | 先提 R，再把三通道拉平，红补偿收益被部分抵消 | 做消融实验：只开红补偿 / 只开白平衡 / 两者都开 |
| E3 | **CLAHE 放大噪声** | 浑水图像噪声大，局部对比度增强后 ORB 特征重复性可能下降 | 用 SLAM 指标（特征数、跟踪长度）评估，而不是只看“好看” |
| E4 | **增强改变颜色分布** | YOLO 若在原始图上训练、在增强图上推理，域偏移明显 | **训练/部署统一**到 `/image_enhanced`，并冻结增强参数（见 `docs/YOLO_REAL_DATA.md`） |
| E5 | **没有时域一致性** | 逐帧独立增强，亮度/色温会闪烁，影响特征匹配 | 加时域平滑或固定参数 |
| E6 | **未与 SLAM 联动评估** | 没有“增强前/后特征点数量、跟踪丢失次数”数据 | 做 A/B 实验，写进 PPT |

#### 3.2.3 相机取流本身也是瓶颈（实测）

2026-11-07 在本机 `HD Webcam`（USB2 480 Mbps）上实测：

| 取流方式 | 分辨率/格式 | 实测帧率 |
|---|---|---|
| OpenCV 直接读 | 1280x720 YUYV | 10.0 fps（格式上限） |
| OpenCV 直接读 | 1280x720 MJPG | 21.7 fps |
| OpenCV 直接读 | 640x480 YUYV | 28.2 fps |
| `v4l2_camera` | 640x480 YUYV | 10.4 fps（内部 yuv422->rgb8 转换慢） |
| `usb_cam` | 1280x720 mjpeg2rgb | 约 2 fps（本机，不推荐） |
| 新增 `camera` 节点 | 640x480 MJPG | 18.9 fps（rclpy 发布开销） |

**结论**：如果 `/image_raw` 本身就低，先别怀疑 SLAM；先看
`v4l2-ctl --list-devices`（video1/video3 是 metadata）、格式（YUYV/MJPG）和
`ros2 topic hz /image_raw`。1280x720 的 YUYV 在 USB2 上就是 10 fps，
必须 MJPG；`v4l2_camera` 在当前版本不支持 MJPG 捕获，所以提供了 `camera` 节点。

> 结论：增强模块目前是“经验参数”，**不能默认它对 SLAM 一定有益**。
> 需要用实验证明：增强后 ORB 特征数、匹配数、跟踪长度是否提升。

### 3.3 几何旁路检测（红色立方体）

#### 3.3.1 流程

`core/cube_geometry.py`：

```text
HSV 颜色分割
  -> 红色通道优势校验（压掉白亮反光）
  -> 形态学开/闭
  -> 轮廓提取 + 多边形逼近
  -> 几何门限（顶点数 4~6、填充率、凸度、长宽比）
  -> 内部棱线分析（Canny + Hough + Harris）
  -> 加权评分 -> NMS -> IoU 跟踪 -> PnP/轮廓拟合测距
```

#### 3.3.2 实测结论（合成数据）

* 6/6 视角检出，IoU 均值 0.968、最小 0.933；
* 顶点数：正视 4、斜视 6，全部正确；
* 单帧测距最大相对误差 0.90%；
* 严格模式（`cube_silhouette`）对红色平面方块 0 误检；
* 跟踪 10 帧发布 9 帧、track_id 恒定为 1。

#### 3.3.3 局限

| # | 局限 | 说明 |
|---|---|---|
| G1 | 颜色阈值依赖水质/光照 | 浑水、背光、红衰严重时 mask 会碎 |
| G2 | 默认 `mode=any` 会接受红色平面方块 | 只有 4 顶点、无内部棱，几何上不可区分 |
| G3 | 单面视角姿态不唯一 | 无纹理对称物体，PnP 有法向二义性 |
| G4 | 遮挡后轮廓不完整 | 顶点数/凸度门限会直接拒检 |
| G5 | 真实水下未验证 | 合成图的颜色/噪声与真实水体差距大 |

> 定位：几何旁路是**数据集未就绪时的可用基线和可解释性对照**，
> 不是最终方案；最终应与 YOLO 做同批真实图片对比。

### 3.4 单目测量与三角化

#### 3.4.1 方法优先级

`core/measurement.py`：

1. `known_size_pose`：4 角点 + `solvePnP(IPPE_SQUARE)`，重投影 ≤2 px；
2. `known_size_refined`：立方体轮廓拟合（循环对应 + PnP 迭代），斜视也成立；
3. `known_size`：正视近似 `Z = f·L/s`，斜视有 ~25% 系统误差；
4. `bearing_only`：只有方向。

关键修正：平面 PnP 的物体原点是**可见面中心**，不是立方体中心；
`measure_geometry()` 按“中心 z 更大”选解，补偿半个边长。

#### 3.4.2 问题

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| M1 | `known_size` 斜视误差大 | 25%~30% | 默认开启 `use_silhouette_fit`，并检查 `method` 字段 |
| M2 | 单帧距离没有不确定度 | 下游无法判断可信度 | 输出协方差或按残差/像素尺寸给置信区间 |
| M3 | 轮廓拟合耗时 | 斜视约 30 ms | 演示机性能不足时 `use_silhouette_fit=false`，但要接受精度下降 |
| M4 | 依赖 `cube_edge_m` 精确 | 边长量错 -> 距离整体比例错 | 卡尺实测，写进配置注释 |
| M5 | 真实水下边缘模糊 | 轮廓抖动 -> 距离抖动 | 多帧滤波 / 多视图三角化 |

#### 3.4.3 三角化

`triangulate_rays()` 解 `min_P Σ ||(I - d dᵀ)(P - o)||²`，用条件数/秩判断退化。
地标节点还做视差、基线、重投影误差过滤。合成数据无噪声误差 ~1e-14 m。

**核心认知**：单目 SLAM 地图不是米。用已知边长算出的“米”直接塞进地图会尺度不一致；
只有 `triangulated` 地标与点云同尺度，`scale_fallback` 只能当临时提示。

### 3.5 跨帧跟踪

`core/tracker.py`：贪心 IoU 匹配（SORT 简化版，无卡尔曼），`min_hits=2` 抑制单帧误检。

问题：

* 快速运动/遮挡时 IoU 关联失败，ID 切换；
* 没有运动模型，鱼群/气泡等动态目标不适合；
* `max_center_jump_px=0` 默认关闭中心跳变约束；
* 跟踪 ID 是地标关联的唯一种子，ID 切换会导致同一物体变成多个地标。

建议：静态目标保持 IoU + `min_hits`；动态目标后续换 ByteTrack/BoT-SORT，
并与 SLAM 的动态 mask 联动。

### 3.6 ORB-SLAM3 单目 SLAM

#### 3.6.1 原理

ORB 特征 -> 初始化（单目需要平移基线）-> 跟踪（恒速模型/关键帧）-> 局部 BA ->
回环检测（DBoW2）-> 全局 BA。输出关键帧位姿、地图点、轨迹。

#### 3.6.2 水下难点

| # | 难点 | 后果 | 对策 |
|---|---|---|---|
| S1 | 低纹理/低对比度 | 特征少、初始化失败、跟踪丢失 | 增强、降低 FAST 阈值、增加特征数、补光/纹理 |
| S2 | 纯旋转 | 单目无法三角化初始化 | 操作时**必须有平移** |
| S3 | 动态目标（鱼、气泡、漂浮物） | 特征被动态物体带走，地图污染 | YOLO 动态 mask 剔除 |
| S4 | 水体散射/悬浮颗粒 | 特征不稳定、误匹配 | 增强/去噪、限制工作距离 |
| S5 | 防水壳折射 | 内参随水深/壳变化 | 水下标定；报告中说明近似 |
| S6 | 无绝对尺度 | 地图单位非米 | 已知尺寸目标恢复尺度；或外部尺度源 |
| S7 | 回环误检 | 轨迹跳变 | 检查 `/slam/status`、限制回环、验证 |
| S8 | 稀疏地图 | 不是稠密重建 | 答辩明确“稀疏点云 + 语义地标” |

#### 3.6.3 工程风险

* C++ 补丁已在本机编译通过，并用 EuRoC 序列验证了位姿/轨迹/点云发布；
  但**真实水下**的初始化与漂移仍未验证（`UNVERIFIED.md` B11）；
* 桥接握手依赖 `settings_file_path_arg` 指向目录，且 `<目录>/<settings_name>.yaml` 存在；
* 时间戳必须严格递增，桥接已做兜底；
* ORB-SLAM3 不是线程安全的，所有 API 调用留在图像回调里。

#### 3.6.4 评价指标

* 初始化时间/成功率；
* 跟踪丢失次数、重定位次数；
* ATE（绝对轨迹误差）、RPE（相对位姿误差）——需要真值（卷尺/标记点/动捕）；
* 回环前后漂移；
* 地图点数、关键帧数；
* 单帧耗时/FPS。

> 没有真值时，至少记录“回到起点后的闭环误差”和“重复跑 5 次的方差”，
> 不要只放一条看起来平滑的轨迹。

### 3.7 语义地标

`core/landmarks.py`：

1. 每个 `track_id` 累积观测（射线 + 位姿）；
2. 按视差/基线筛选；
3. 线性最小二乘三角化；
4. 重投影误差剔除离群观测；
5. 输出 `triangulated` 或 `scale_fallback`。

优点：

* 尺度语义清楚（绿=地图同尺度，黄=相机系近似）；
* 合成数据三角化误差 ~1e-14 m；
* 没有位姿时不会假装有地图尺度。

问题：

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| L1 | ~~没有类别白名单~~ **已补** | YOLO 的鱼/气泡也会被三角化 | `landmark_class_names` + `min_detection_confidence`（2026-11-07 实现） |
| L2 | track_id 跨回环/重定位不保持 | 同一物体分裂成多个地标 | 用地图点/外观/位置融合 |
| L3 | 没有协方差/不确定度 | 无法判断地标可信度 | 输出协方差或观测数/视差 |
| L4 | `min_baseline_m` 在地图单位下不是米 | 参数名易误解 | 改名或注释清楚；按地图尺度自适应 |
| L5 | 只输出点，不输出物体尺寸/朝向 | 语义地图信息少 | 用检测框/立方体尺寸估计 extents |
| L6 | 没有地图保存 | 重启丢失 | 保存 JSON/CSV 或接入 SLAM 地图保存 |
| L7 | 未与真实点云做一致性检查 | 尺度/外参错误不易发现 | 比较地标到最近地图点距离 |

* 训练用 `/image_raw`、部署用 `/image_enhanced` -> 颜色/对比度域偏移；

* 类别名顺序与 `data.yaml` 不一致 -> 框对了但类别错。

## 7. 关键公式（PPT 可直接用）

针孔投影：

```text
[u, v, 1]ᵀ = K [R | t] [X, Y, Z, 1]ᵀ
```

已知边长测距（正视近似）：

```text
Z = f · L / s
```

其中 `f` 为焦距（像素），`L` 为目标真实边长（米），`s` 为像素边长。

三角化（射线最小二乘）：

```text
min_P Σ_i ||(I - d_i d_iᵀ)(P - o_i)||²
(P = 世界点，o_i = 相机光心，d_i = 世界系射线方向)
```

尺度说明：

```text
单目 SLAM 地图：X_map = s · X_true，s 由初始化基线决定，未知
已知尺寸目标：s = L_true / L_map（可用于恢复米制尺度）
```

## 8. 实验设计与验收指标

| 实验 | 变量 | 指标 | 通过标准（建议） |
|---|---|---|---|
| 标定 | 水上 vs 水下 / 不同水深 | RMS、fx/fy、主点、去畸变目检 | RMS < 0.5 px，边缘直线 |
| 增强 | 关 / 红补偿 / 白平衡 / CLAHE | ORB 特征数、匹配数、跟踪长度、FPS | 增强后跟踪更稳，不是只看图 |
| 几何旁路 | 清水/浑水/距离/角度 | 检出率、误检数、距离误差 | 真实图检出率 ≥80%，距离误差 <10% |
| YOLO | 不同模型/尺寸/设备 | mAP50、mAP50-95、每类 Recall、FPS | 按场景定；小目标/遮挡单列 |
| SLAM | 有/无增强、有/无动态 mask | 初始化成功率、丢失次数、ATE/RPE | 能初始化、轨迹连续 |
| 语义地图 | 有/无类别白名单 | 地标数、错误地标数、与点云距离 | 动态目标不生成地标 |
| 测距 | 10 个已知距离 | 绝对/相对误差 | 中近距离 <10% |

## 10. 结论

* 当前代码的**算法层是可信的**：合成数据 + 99 项测试覆盖了标定、检测、跟踪、测距、三角化；
* **真实环境仍未验证**：水下标定、真实相机、ORB-SLAM3 编译与联调是下一阶段的核心风险；
* 本次新增的标定 GUI、数据集采集/检查、真实环境 YOLO 配置，把“从真实相机到可训练数据”的链路补齐了；
* 答辩时最重要的不是“我们做了很多模块”，而是**说清楚每个数字是在什么数据上得到的**，
  以及**单目尺度、折射、动态目标、稀疏地图**这四个限制如何处理。
