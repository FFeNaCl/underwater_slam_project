## 4. 【实际操作①】水下相机标定

> 为什么必须自己做：防水壳引入"空气-玻璃-水"折射，普通针孔模型只是近似；
> 内参是检测测距、SLAM、去畸变的共同基础。**若防水壳/水深/镜头到玻璃距离改变，需重标。**
> 完整原理与失败案例见 `docs/CALIBRATION.md`。

### 4.1 准备标定板（8x6 内角点 = 9x7 格，每格 25 mm）

1. 打印棋盘格：A4 打印（每格 25 mm，打印后**用卡尺量**，打印缩放会改变实际尺寸！）。
2. 防水处理（任选）：
   * 塑封（过塑机）——最便宜；
   * 贴在亚克力板上（**必须压平，不能有气泡/波浪**，否则角点提取失败）；
   * 防水贴纸贴到硬质板。
3. 板必须**刚性、平整**；周围留白边（quiet zone）帮助角点检测。

### 4.2 采集标定图像（20~30 张，最少 12 张）

规范（直接照做）：

* 相机和标定板**都在水下**，水质尽量接近真实实验；
* 板出现在画面**四角、中央、不同远近**，覆盖不足报告会警告；
* 每张与相机平面成 ±20°~40° 倾斜（不要全都正对）；
* 用**增强后**的图像标定（与实际使用一致）：先启动相机+增强节点（见第 7 节），
  或者直接拍原图离线标定后，注意 SLAM 用的也是同一链路图像；
* 避免：运动模糊、过曝反光、只拍中央、只有小角度变化。

三种采集方式任选：

| 方式 | 命令 | 适用 |
| --- | --- | --- |
| **A. 图形界面（推荐现场）** | `python3 -m underwater_perception.tools.calibrate_gui`（界面里直接改图案/内角点/方格毫米数；SPACE 采集、C 标定） | 标定板参数需要反复改、现场可视化操作 |
| **B. 离线图片** | 相机拍好 20~30 张存到 `~/calib_images/`，再跑 4.3 | 最容易控制质量、可重跑 |
| C. USB 相机交互采集 | `python3 -m underwater_perception.tools.calibrate_cli --camera 0 --capture 25 --out ./calibration_out --fourcc MJPG --camera-fps 30`（SPACE 拍摄 / q 退出；`/dev/video1` 常是 metadata，别用 1） | 没有 ROS 时的快速方案 |
| D. ROS 节点自动采集 | `ros2 launch underwater_perception calibration.launch.py image_topic:=/image_enhanced`（自动每 1.0 s 捕捉；服务 `~/capture` 手动拍、`~/run` 开始标定、`~/reset` 清空） | 标定"增强后"图像的正式方案 |

### 4.3 标定并生成四件套输出

```bash
python3 -m underwater_perception.tools.calibrate_cli \
  --images ~/calib_images \
  --cols 8 --rows 6 --square 0.025 \
  --out /home/hu/underwater_slam_project/calibration_out
```

（`--cols 8 --rows 6` 是**内角点**数，与 `cameracalibrator --size 8x6` 一致；`--square 0.025` 单位是**米**。）

输出目录 `calibration_out/` 四件套：

| 文件 | 干什么用 |
| --- | --- |
| `ost.yaml` | ROS camera_calibration 兼容格式，存档/对比 |
| `water_1280x480.yaml` | **ORB-SLAM3 配置文件**（含 `%YAML:1.0` 头、Camera.* 键） |
| `enhancer_camera_params.yaml` | 增强节点的 camera_matrix / distortion_coeffs |
| `calibration_report.json` + `undistorted/` | 结题报告数据 + 去畸变目视检查图 |

### 4.4 验收标准（不达标就重采）

* 重投影误差 **RMS < 0.5 px**（0.5~1.0 可接受，>1 重采）；
* fx / fy 相差 < 2%，主点 (cx, cy) 接近画面中心；
* 单视角点误差 ≤ 3 倍平均（报告会列出最差 3 张，删掉重跑）；
* 打开 `undistorted/*.jpg`：**边缘直线不再弯曲**；
* 报告无"覆盖不足"警告。

### 4.5 把标定结果装进系统（三步，做完才能用）

```bash
# ① ORB-SLAM3 配置：复制到 orb_slam3_ws 的 Monocular 配置目录
cp /home/hu/underwater_slam_project/calibration_out/water_1280x480.yaml \
   /home/hu/underwater_slam_project/src/ros2_orb_slam3/orb_slam3/config/Monocular/water_1280x480.yaml
```

② 增强节点：编辑 `/home/hu/underwater_slam_project/config/enhancer_underwater.yaml`，
把 `enhancer_camera_params.yaml` 里的 `camera_matrix`（行优先 9 个数）与
`distortion_coeffs`（k1 k2 p1 p2 k3 共 5 个数）填进去，并设 `use_undistort: true`。

③ （可选，几何旁路测距需要）编辑 `src/underwater_perception/config/cube_detector.yaml`
与 `config/semantic_landmark.yaml`，填入 fx/fy/cx/cy。

> 根目录的 `config/water_1280x480.orbslam3.example.yaml` 和包内
> `src/underwater_perception/config/orbslam3/water_1280x480.yaml` 里的 fx=fy=700
> 都是**占位值**——直接用会导致跟踪失败或尺度错误，标定后必须替换。

```text

│   └── labels/*.txt       # 每行: class_id cx cy w h（全部归一化到 0~1，中心点+宽高）

    └── labels/*.txt
```

`data.yaml` 示例：

```yaml

```

### 5.3 标注规范（决定模型上限）

* 补充**真实水下/水面实拍**图（目前数据集多是水面/门控相机图），每条视频抽帧，间隔≥1 s 防重复；
* **负样本**：不含任何目标的纯水/背景图，什么都不框；
* **小目标**：远处小船/浮标也要框（模型对小目标漏检是常见短板）；
* **遮挡**：被浪/杂物挡住一半的目标照框，框可见部分；
* 类别边界要一致（比如"离岸平台"归 research_platform 还是 platform，定一次就执行到底）。

## 6. 几何旁路（红色立方体）调参

YOLO 没就绪时用这个顶替（输出与 YOLO 相同的 `/detections` JSON 契约，下游无感知）。

```bash
# 先用合成画面确认能跑
python3 -m underwater_perception.tools.cube_detect_cli --synthetic --out ./cube_demo_out

# 真实水下图片调阈值：--print-mask 把掩码存下来看，比在代码里猜快得多
python3 -m underwater_perception.tools.cube_detect_cli --input ~/real_underwater_imgs --print-mask --out ./cube_demo_out
```

调参顺序（对应 `src/underwater_perception/config/cube_detector.yaml`）：

1. `color_preset` / `hsv_ranges`：用 `--print-mask` 看掩码是否盖住立方体、避开背景；
2. `min_area_px` / `max_area_fraction`：排除过大过小干扰；
3. `mode`：默认 `any` 保召回；出现"红色平面方块"误检时改 `cube_silhouette`；
4. `min_confidence` / `min_fill_ratio` / `min_convexity`：最后再动；
5. `cube_edge_m`：**改成实物边长（米）**，默认 0.05 是 5 cm 立方体——测距全靠它；
6. 标定完成后把 fx/fy/cx/cy 填进本文件，测距才准。

实测验收（UNVERIFIED B7/B8/B10）：

* 50~100 张真实水下图上跑 `cube_detect_cli --input <dir>`，记录检出率、平均置信度、误检数；
* 距离实测：固定 10 个距离（如 1~3 m 每 20 cm 一次）对照卷尺，记录误差百分比；
* 把实测 HSV 值以"实测于 <日期/水质/距离>"注释写回 cube_detector.yaml。

## 8. SLAM 链路（ORB-SLAM3 单目 + 语义地标）

前置：第 2 节两个工作区已编译；第 4.5 节已把 `water_1280x480.yaml` 放进 Monocular 目录。

```bash
# 终端 1：SLAM 节点（C++，补丁版）
ros2 launch underwater_perception slam_pipeline.launch.py \
  voc_file:=$HOME/orb_slam3_ws/src/ros2_orb_slam3/orb_slam3/Vocabulary/ORBvoc.txt.bin \
  settings_dir:=$HOME/orb_slam3_ws/src/ros2_orb_slam3/orb_slam3/config/Monocular/ \
  settings_name:=water_1280x480 \
  rviz:=true
```

（`settings_dir` 必须是**目录**且以 `/` 结尾，yaml 必须在该目录里。）

验证顺序：

1. 握手：`ros2 topic echo /mono_py_driver/exp_settings_ack --once` → `data: ACK`；
2. 供图：启动第 7 节的 underwater_pipeline（或 `full_demo`），`ros2 topic hz /mono_py_driver/img_msg` 有流；
3. 跟踪：`ros2 topic echo /slam/status --once` → `tracking_state: OK`（code 2）；
4. 位姿/点云：`ros2 topic hz /slam/pose` ≈ 图像帧率；`/slam/map_points` 1 Hz；`ros2 run tf2_ros tf2_echo map camera`；
5. 语义地标：`ros2 topic echo /semantic/landmarks --once` → `source: triangulated`（与地图同尺度）。

**水下初始化技巧**（LOST / 一直 NOT_INITIALIZED 时）：

* 需要**平移**：手持相机横向缓慢移动（旋转不动初始化不了）；朝向池底/池壁/石头等有纹理处；
* 用 `/image_enhanced` 而不是 `/image_raw`；
* 调高 ORB 特征：`water_1280x480.yaml` 里 `ORBextractor.nFeatures: 1800~2500`、
  `iniThFAST: 10~12`、`minThFAST: 5~7`（低纹理水下）；
* 跟踪丢失仍会发布"最后成功位姿"——下游必须看 `/slam/status` 判断可信度；
* 注意：**单目尺度不是米**，位姿与三角化地标只有"地图尺度"意义，报告里要如实说明。

## 12. 常见故障速查

| 现象 | 处理 |
| --- | --- |
| launch 报 `parameter not found` | `ros2 launch <包> <file> -s` 看实际参数名 |
| `/detections` 空 | `cube_detect_cli --print-mask` 调 HSV；检查 min_area_px / min_confidence / mode；注意 `track_min_hits=2` 前几帧本来就抑制 |
| SLAM 一直 NOT_INITIALIZED | 检查 ACK；settings_dir 必须是目录；低纹理→nFeatures↑ iniThFAST↓；需要平移 |
| RViz `Fixed Frame [map] does not exist` | 握手未完成，SLAM 还没发布 TF |
| 地标全是 scale_fallback | 没有位姿输入或 frame 不匹配 |
| 标定 `not enough views` | 内角点数/格子尺寸填错；≥12 张（建议 20~30） |
| 标定后 SLAM 反而更差 | 标定条件变了（防水壳/水深）；标定只用中央视角会"假好" |
| 类别名与预期不符 | 检测类别来自模型元数据/数据集 data.yaml（§5.1 决策点） |
