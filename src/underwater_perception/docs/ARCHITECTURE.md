## 2. 分层（为什么这样分）

| 层 | 位置 | 依赖 | 是否可在无 ROS 环境测试 |
|---|---|---|---|
| 纯算法 | `underwater_perception/core/` | numpy / opencv / pyyaml | ✅ 有 99 项 pytest + 合成数据自测 |
| ROS 节点 | `underwater_perception/nodes/` | rclpy + 标准消息 | ❌ 只能在 Linux + ROS 上跑 |
| 命令行工具 | `underwater_perception/tools/` | core | ✅ 开发机上真跑过 |
| 第三方 SLAM | `orb_slam3_ws/.../ros2_orb_slam3/` | ROS2 + Pangolin + Eigen | ❌ 需编译 |

**这条分层的实际价值**：开发机是 Windows、没有 ROS2，如果算法和 ROS 混在一起，
就完全无法验证任何东西。现在"识别/跟踪/测距/标定/三角化"这些**真正容易出错的部分**
都能在没有 ROS、没有相机的情况下跑真实测试；ROS 节点只是几十行的适配层，
出错面被压到最小。

## 3. 关键设计决策

### 3.1 为什么先做"几何旁路"而不是等 YOLO 数据集
立方体是有严格几何定义的物体：轮廓是凸多边形（顶点数 = 可见面数 + 3），
填充率有确定范围（正方形 1.0、正六边形 ≈0.87），三面视角内部还有 Y 型顶点与三条棱。
这些判据**不需要任何训练数据**就能把立方体从红色平面色块里区分出来。
YOLOv8 数据集就绪后，把 `yolo_detector` 挂到同一条 `/detections` 契约上即可无缝替换。

### 3.2 为什么检测器同时保留"宽松"和"严格"两种模式
* `mode: any`（默认）：只要有颜色 + 轮廓几何证据就报，**保召回**。代价是红色平面方块也会被报。
* `mode: cube_silhouette`：额外要求"轮廓内部有棱线结构证据"（方向数/线长占比/角点响应），
  **能拒掉红色平面方块**（合成测试中验证过）。代价是单面正视视角会被拒。

现场建议：先用 `any` 确认能检到，出现误检再切 `cube_silhouette`。

### 3.3 为什么单帧距离要"轮廓拟合"而不是"正视假设"
正视假设 `Z = f·L/s` 在斜视时会有 **25~30% 系统误差**（开发机实测），
而斜视恰恰是水下拍摄最常见的视角。解决办法：把已知边长的立方体**拟合到观测轮廓**
（循环对应 + PnP 迭代，多起点避免局部极小），任意视角都成立，实测误差降到 **<1%**。
代价是斜视时每帧多花约 30 ms（正视有早退，约 1 ms），可用 `use_silhouette_fit: false` 关掉。

### 3.4 为什么地标必须"三角化"而不是"用像素大小算距离"
单目 SLAM 的地图尺度由初始化基线决定，**不是米**。
用已知边长算出的"米"直接放进地图会与其他地图点、轨迹尺度不一致，
RViz 里表现为"地标和点云对不上"。三角化得到的地标与地图同尺度，才是正确的做法。
没有位姿时的 `scale_fallback` 明确标注为"相机系近似"，颜色也用黄色区分。

### 3.5 坐标与单位约定（全文一致）
* 相机光学坐标系：`x` 右、`y` 下、`z` 前（OpenCV）。
* 世界/地图系：单目无绝对尺度；`/slam/pose` 等发布 **Twc（世界<-相机）**。
* 方位角：`azimuth = atan2(x, z)`（右为正），`elevation = atan2(y, hypot(x,z))`（下为正）。
* 所有像素坐标 `(u, v)` 原点在左上；棋盘格参数是**内角点**数，长度单位**米**。

### 3.6 时间与线程
* ORB-SLAM3 **不是线程安全的**：补丁把所有 SLAM 访问都放在图像回调里，
  点云发布用 `point_publish_period_ms` 限频而不是另开线程。
* 桥接节点保证时间戳**严格递增**（`min_dt_s`），否则 ORB-SLAM3 会丢帧或行为异常。
* 检测节点用 `max_rate_hz` 限频，几何法通常不需要（单帧 <5 ms，斜视拟合 ~30 ms）。

## 4. 关键参数如何互相影响（调参顺序）

1. `color_preset` / `hsv_ranges` → 决定掩码质量（用 `--print-mask` 看）
2. `min_area_px` / `max_area_fraction` → 排除过小噪点与过大反光
3. `mode` → 召回/精度取舍
4. `min_fill_ratio` / `min_convexity` / `min_aspect_ratio` → 形状筛选
5. `min_confidence` → 最后的总门限
6. `cube_edge_m` + 相机内参 → 决定测距是否有物理意义（**必须与实物一致**）

## 5. 性能预算（开发机合成数据实测，仅作量级参考）

| 环节 | 耗时 |
|---|---|
| 颜色分割 + 形态学 + 轮廓（1280×480） | 2~4 ms |
| 几何验证 + 内部棱线分析（每候选） | 0.5~2 ms |
| 轮廓拟合（正视，早退） | ~1 ms |
| 轮廓拟合（斜视，多起点） | 25~35 ms |
| 三角化（每地标每次更新） | <0.1 ms |

真实图像（含更多候选轮廓）会更慢；需要提帧率时按 `AI_HANDOFF.md §7` 的顺序调。
